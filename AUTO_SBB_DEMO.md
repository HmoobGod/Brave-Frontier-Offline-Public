# Optional Auto use of the existing experimental SBB

Auto can opt into the already implemented experimental offensive SBB prototype.
Both the new Auto option and existing experimental SBB combat must be enabled.
The new option starts off and is not persisted. Existing Auto behavior is retained
when either option is off, outside archive Auto, for unsupported forms or gauge,
and for actors blocked by Curse or Paralysis. The previous planner runs first;
only offensive burst choices can be upgraded, preserving support priorities and
Advanced Auto conservation. No normal attack is promoted into a burst.

This is an explicitly DEMO policy, not recovered native Global Auto AI. It uses
BF044's existing source-qualified SBB names/targets and simulated combat with the
existing 100% prototype gauge. Native second-tier charging, secondary effects,
UBB, mastery, inventory and rewards are not introduced. Existing execution-time
status, source and disabled-prototype fallback checks remain authoritative.
Changing the new option affects future plans, rather than cancelling an action
already in progress. Manual command selection is unchanged.

The regression runs actual scheduled Auto turns with an enemy-phase stop, checks
planned actions, gauge and affected enemies, plus negative qualification/support/
conserve/manual/training controls and full synthetic progression/storage guards.
It also verifies idempotent installation. Existing v105 runtime and packaged
checks include the feature, with no new workflow rules or triggers. Fresh native
CI and independent exact-head review are required before integration; synthetic
browser tests do not establish original SBB parity or device/save acceptance.
